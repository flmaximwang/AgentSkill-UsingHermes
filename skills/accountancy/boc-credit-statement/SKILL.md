# 中国银行信用卡账单（PDF）

卡：`5257 **** **** 9393`（抬头「信用卡卡号」）→ 账户 `中国银行信用卡-9393`（负债科目 2241）。
来源键 `boc_credit`，解析模块 `Scripts/parsers/boc_credit.py`，档案 `Config/bank_profiles.yaml` 的
`中国银行信用卡`。**与「中国银行借记卡 3358」是两份完全不同的文件，别混。**

## 文件形态

| 位置 | 内容 |
|---|---|
| 第 1 页 | 抬头：客户姓名 / 信用卡卡号 / 到期还款日 / 账单日 / 本期应还款额（RMB + USD）/ 最低还款额 |
| 第 1 页 | 人民币账户汇总：上期存款/欠款余额 · 本期支出金额 · 本期存入金额 · 本期存款/欠款余额 · 最低还款额 |
| 第 1 页 | 人民币交易明细表头：`交易日 | 银行记账日 | 卡号后四位 | 交易描述 | 存入 | 支出` |
| 第 2~3 页 | 人民币交易明细（续） |
| 末页 | **美元账户**汇总（同结构）+ 美元交易明细（同样六列，金额是美元） |

账单周期 =（上月 15 日，本月账单日 14 日]。文件名按周期：
`中国银行信用卡_9393_<上月15日>_<本月账单日>.pdf`（如 `中国银行信用卡_9393_20260515_20260614.pdf`）——
**交易日在周期内跨月**（06 月账单含 05/16~06/14），normalize 按交易日归月，不按文件名归月。

## 解析陷阱（都踩过）

1. **金额是「存入 / 支出」两列**，不是带符号一列 → 档案必须写 `debit: 支出` / `credit: 存入`，
   让 `direction_of` 按「支出列非空 = out」判方向；金额用模块的 `amount_of`（支出优先，其次存入）。
2. **交易描述折行**（`支付宝-上海壹佰米网络科\n技有限公司CHN`）→ pdfplumber 已把折行放进同一格，
   strip 掉换行即可，**不要按物理行拼**（与中行借记卡流水的折行陷阱不同）。
3. **交易日只有 MM/DD，没有年份** → 年份按账单周期推：交易日月份 ≤ 账单月份 → 账单年，否则账单年 − 1
   （01 月账单里的 `12/23` 是 **2025**-12-23）。
4. **表头/汇总行会混进表格** → 只认第一列形如 `MM/DD` 的行；`交易日` 表头**出现两次**（人民币段、美元段），
   用出现次序区分，只取第一段。
5. **汇总行的表头与数据是两行**（表头 `上期存款/欠款余额…`，下一行才是 `欠款2274.97 1357.30 …`）；
   数值带「欠款/存款」前缀，取数前要剥掉，否则 `money.D` 判成 0.00。
6. **美元段是另一个币种**：账本是人民币口径、美元无汇率凭据 → 只出人民币行，美元段只当锚点核对
   （美元欠款另记在资产表备注里）。
7. **还款行不写还款卡片**：交易描述只有 `BOCNET`（中行网银/手机银行）、`支付宝CHN`、
   `还款成功 , 谢谢 !`、`无法足额扣款，请补足账户余额`（代扣部分成功）—— 没有卡号/账号。
   资金来源**只能靠资金侧按「日期 + 金额」配对**（借记卡/支付宝流水里那笔转出），配上就跳过账单侧这行，
   否则同一笔钱入账两遍。配不上的 = 钱来自没有流水的账户（例：2026-03-20 存入 198.00 描述「支付宝CHN」，
   不在支付宝 8239 流水里 → 用户另一支付宝 0156）。

## 逐份护栏（模块里跑，别绕过）

`check_records` 用账单自己的四数核对：

- Σ支出明细 == 本期支出金额，Σ存入明细 == 本期存入金额
- 上期余额 + 本期支出 − 本期存入 == 本期余额

对不上直接抛错，**先别入账**。（第一次实现时把汇总的「表头行」当数据行 → 全 0.00，护栏立刻抓到。）

## 记账口径

- **美元消费按实际购汇汇率折算**（方案 A，用户 2026-09-23 确认）：
  - 02/03/04 期美元消费（4.00+9.00+10.00=23.00）由 2026-05-05 购汇清偿 → 汇率 **6.8513**
  - 05/06/07 期（30.56+49.99+10.00+1.76+5.00+1.50=98.81）由 2026-08-05 购汇清偿 → 汇率 **6.7630**
  - 不单列汇兑损益；写成 `Config/adjustments.yaml` 的单笔分录（借 费用/财务费用 ｜ 贷 boc_credit），
    8 条合计 **764.17 元**（＝825.83 − 03 期 61.66）；03 期 9.00、08 期 5.00 未入账（缺凭据）。
  - 调整分录的 **id 必须唯一**：同一个月可能有多笔美元消费（2026-05 就有两笔）→ id 用**完整交易日**
    （`调-2026-05-06-美元消费-9393`）；用 `调-YYYY-MM-…` 会被 `book` 以「调整分录 id 重复」报错退出。
- **消费（支出列）**：借 费用/资产 ｜ 贷 `2241—中国银行信用卡-9393`
- **分期行**（`<00x/00y>自由分期`、`商户分期`、`账单分期`、`分期利息`）：分期本金是原消费的重记，
  `自由分期成功，冲销原交易金额`（存入列）冲减原交易 → 两行要成对处理，否则费用重复或漏记
- **还款行**（`BOCNET`/`支付宝CHN`/`还款成功`/`无法足额扣款`）：借 `2241—9393` ｜ 贷 资金侧，
  与资金侧配对后**跳过账单侧**（保留资金侧）
- **退款行**（如 `（特约）中国铁路网络有限公司CHN`）：借 `2241—9393` ｜ 贷 原费用（冲减）
- **财政贴息**（`自由分期-财政贴息`，0.69/0.30）：冲减分期利息

## 接线清单（新增这类来源时）

1. `Config/bank_profiles.yaml` 加 `中国银行信用卡` 段（source / columns / accounts / out_stem / out_dir）
2. `Scripts/parsers/boc_credit.py` 模块（read_cells / check_profile / amount_of / check_records）
3. `Scripts/parsers/__init__.py` 的 `PARSERS` 登记
4. **`detect_profile` 要按「命中关键词最长」选档案**：`中国银行信用卡_9393_….pdf` 同时含「中国银行」
   与「中国银行信用卡」，按定义顺序取第一份会把信用卡账单认成借记卡流水（已修为最长优先）
5. 文件放 `Running Account/中国银行信用卡/`，原始导出留在 Downloads（只读）
6. **`Scripts/books.py` 把信用卡当资金侧**：模块常量 `_CARD_SIDE = ("bank", "boc_credit")` 用在
   `pair_card_funded` 的两个池子与 `tracked` 上，`_funding_is_tracked` 允许 `code in ("1002", "2241")`。
   效果：平台侧「结算方式＝中国银行信用卡(9393)」的消费/退款 → 与账单侧同额同日配对，
   **保留账单侧**、跳过平台侧，并把平台侧的商品说明回填进账单行摘要
   （实测：账单行变成「支付宝-上海蓝色商道…CHN｜平台业务：OralB欧乐B电动牙刷…｜美容美发」）。
