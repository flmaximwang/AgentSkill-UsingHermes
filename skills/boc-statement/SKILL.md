# 中国银行借记卡流水（PDF）

- 账户 / 资金科目：`中国银行借记卡-3358` → `accounts.boc_card`（1002 银行存款）
- 档案：`config/bank_profiles.yaml` → `profiles.中国银行`
- 样例文件：`~/Downloads/流水/中国银行/中国银行_3358_20260801_20260831.pdf`（7 页）
- 导出账号：`3358`（档案 `accounts["3358"]`，内容证据 = 抬头「借记卡号：6235710800000363358」）——
  文件名里没有账号段时靠它认账户；卡号与文件名矛盾就报错

## 文件形态

标题「中国银行交易流水明细清单」，首页信息块含：交易区间、客户姓名、借记卡号、
**借方发生数 / 贷方发生数**（用于对账锚点）、账号、页数 x/y、行数。
表格列（表头位于第 4–6 物理行）：

```
记账日期 | 记账时间 | 币别 | 金额 | 余额 | 交易名称 | 渠道 | 网点名称 | 附言 | 对方账户名 | 对方卡号/账号 | 对方开户行
```

## 解析要点（踩过的坑）

1. **金额是单列带符号**：负号 = 支出（账户减少），正号 = 收入。不是借方/贷方两列。
2. **金额与余额是右对齐列**，摘要/对方/附言是左对齐列：按「词左边距对齐列左边界、
   或词右边距对齐列右边界」分列（`pdf_table._assign`），否则数字会串列。
3. **长文本折行**：附言「支付宝-支付宝小荷包-自动攒」、对方户名会折到下一物理行且无日期，
   必须并入上一条记录，不能当成新记录。
4. **户名与卡号粘连**：对方账户名列宽仅约 5 字，户名溢出后与卡号之间**没有空格**，
   pdfplumber 会读成一个词（如 `支付宝支付科技有限公20886220676450310156`）。
   按与各列的 x 重叠宽度切分（`pdf_table._split_word`）才能还原。
5. 末页有 `----------END-------`、`温馨提示`、页码，需跳过；首页信息块不是数据行。
6. 每页表头会重复出现，只认第一处表头，其后的行按数据行处理。
7. **同一天的明细在 PDF 里是倒序（最新的在前）**：任何「某日/某期最后一笔」的逻辑都必须按
   **完整时间戳**排序，不能只按日期 —— 只按日期排序时同日多笔的先后由文件顺序决定，
   会取到当天**最早**那笔的余额（实测 2026-04 的期末余额因此差 4,450.00，并伪造出 11 个假差额）。
   `balances._stamp()`（14 位 YYYYMMDDHHMMSS，缺时间补 0）就是干这个的；建行只有日期，退回 00:00:00。

## 余额链自检（比「文件自带笔数/收支合计」更强的证据）

流水自带「余额」列 → 可以逐笔验算 `余额_i − 余额_{i−1} == ±金额_i`（`python -m Scripts balances`
的余额链自检）。它抓的是**锚点抓不到**的错：笔数与收支合计都对得上，仍可能是
「少解析一笔 + 多解析一笔」或收支方向记反 —— 余额链对不上就是解析错了。

- 2026-01~08 四个银行账户 **2037 笔，断点 0**（唯一例外是**同一秒内的多笔**：中行出现过
  2 组同秒并列，先后不可知，组内互换不算问题，`balances._walk_chain()` 用贪心找一条能走通的顺序）。
- 用「≤ 期末 23:59:59 的最后一笔余额」当期末余额 → 与账本「统计」表逐期勾稽
  `上期余额 + 本期净变动 = 本期余额`，四张卡 2026-02~08 全部为 0.00。

| 交易名称 | 方向 | 分录 |

| 银联入账 / 网上快捷提现（对方含支付宝、财付通） | 收入 | 借 银行存款；贷 其他货币资金—支付宝/微信/小荷包 |

| 银证转账（对方为国信证券等） | 双向 | 借 短期投资—国信证券-3163；贷 银行存款（转入证券反向） |

| 消费类（无明确用途） | 支出 | 待分类（不得猜） |

## 按月拆分（PDF 专用）

银行 PDF 不能整页复制：**月份边界落在页中间**（这份 31 页里第 5/9/14/18/22/24 页跨月），整页复制会把同一笔
带进两个文件 → 重复入账。`python -m Scripts split <pdf>` 按抽出的明细**重排**生成派生件：保留原列名与原取值、
页首标注「派生件（非银行原始回单）+ 源文件名 + 借记卡号/账号/客户 + 期间 + 本页笔数/支出/收入」，写盘前回读自检。
抬头里的「页数 1/31」「借方发生数 552.80」「行数 15」这类**只对原件成立**的数字不得搬进派生件。
