# 配对链的分支速查（`Scripts/books.py`）

`book()` 里的配对链**顺序固定**，每条只管一类场景，候选池与「保留哪一侧」各不相同 ——
改任何一条之前先在这里对一遍，别凭印象动。

```
pair_by_uid → pair_jd_duplicates → pair_internal_transfers → pair_card_funded → pair_own_account_transfers
```

## 各分支的判定与归属

| 分支 | 认什么 | 候选池 | 保留侧 | 跳过侧 |
|---|---|---|---|---|
| `pair_jd_duplicates` | 京东回单与微信/支付宝/银行同笔（白条分分卡通道、南京银行 0134、中行 3358/建行 2464） | 既有账户侧 | 既有账户侧（回填商品说明） | 京东侧 |
| `pair_internal_transfers` | 平台提现 ↔ 银行到账（含手续费容差 `(0, 0.1%]`） | `bank_in`，按渠道过滤 | **平台侧**（手续费可见） | 银行侧 |
| `pair_card_funded`·卡结算 | 平台支出由某张**已导出借记卡**结算 | `bank_out`/`bank_in` | 银行侧（回填平台摘要） | 平台侧 |
| 同上·基金卖回 | 「蚂蚁财富…卖出/赎回到银行卡」 | `bank_in` | 银行侧 | 平台侧 |
| 同上·退款原路退回 | 摘要含「退款」+ 卡结算 + `收支 in ("in","neutral")` | `bank_in` | 银行侧 | 平台侧 |
| 同上·回卡类 | 「转出到银行卡/提现」+ `收支 in ("neutral","in")` | `bank_in` | 银行侧 | 平台侧 |
| 同上·合并付款 | 银行侧一笔 = 平台侧多笔之和（子集和，≤12 笔、解唯一） | 同日同卡平台侧行 | **平台侧逐笔**（粒度更细） | 银行侧汇总 |
| `pair_own_account_transfers` | 本人两张卡的划转两端 | 对方账号已登记的自有账户 | 转出侧 | 转入侧 |
| `pair_by_uid` | 平台侧备注里的 `配对UID:xxx` | 按 UID 分组 | 平台侧逐笔 | 银行侧（解唯一才动手） |

## 断链（本次最大的坑）的两种成因

几条分支**各跑一遍，互相看不见对方跳过了什么**，于是「A 因『P 会入账』跳过、P 又因『B 会入账』
跳过」而 A 与 B 不是同一笔 → 两头都没入账。

1. **渠道错配**：平台侧是支付宝的行，却配到银行侧写着「财付通」的流水（同额同日）。
   → 候选池先过 `_channel_ok()`。
2. **一笔银行流水被两套规则争用**：银行侧「转给本人另一张卡」的划转被平台配对抢走并回填摘要。
   → 构建 `bank_in/bank_out` 时排除 `own_account_item()` 命中的行。

## 修完必做的验证

- 银行逐账户勾稽**逐期为「一致」**（银行侧没被动过）；
- 两侧金额合计**逐分相等**（如「银行侧买入 ↔ 支付宝侧买入」那类）；
- 逐期扫一遍「配对与问题」表（跳过条数会变，属正常）；
- 凭证数与借贷合计对照改动前的值 —— 一次性跳很多说明改宽了。
