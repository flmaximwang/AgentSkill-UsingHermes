# Tushare Pro API 访问层（权限 / 更新时间 / 限频）

tushare / tushare-data 这类 skill 管「取什么数、怎么分析」；本 skill 管**访问层**：能不能调、什么时候有数据、会被限多少频次。做数据同步/批量拉取前先查这里。

## 何时使用
- 用户问「XX 数据什么时候更新 / 几点能拉」
- 用户说「我积分不够但能调某接口」（文档与实测冲突）
- 批量同步（全市场股票/ETF/指数）前评估是否会撞频控
- 需要判断账号实际积分档位
- 写/查 TradingRazer2 的 tushare 增量同步调度时

## 数据更新时间（官方口径，2026-08 核对）
| 数据 | 接口 | 更新时间 |
|---|---|---|
| 股票日线 | daily | 交易日 15:00–16:00 入库 |
| 指数日线 | index_daily | 15:00–17:00（pro_bar 集成口径；第三方文档称每日 9:00 与 19:00 双更） |
| ETF/场内基金日线 | fund_daily | 收盘后，同批 15–17 点 |
| 每日指标 | daily_basic | 15:00–17:00 |
| 分钟数据 | stk_mins 等 | 17:00–21:00（需单独开权限，不在积分体系内） |

**稳妥同步窗口 = 交易日 17:00 之后**：一次把 stock+index+fund 全补齐；次日早 9 点前后可能还有一轮修订，在意前一日准确性可再增量一遍。

## 积分档位与限频（doc_id=290）
| 积分 | 每分钟频次 | 每天总量 | 价格 |
|---|---|---|---|
| 120 | 50 | 8000 次/天 | 0 |
| 2000+ | 200 | 10 万次/API | 200 元/年 |
| 5000+ | 500 | 常规无上限 | 500 元/年 |

分钟、港美股、实时行情 = 单独开权限，不占积分（doc_id=290 表二）。

## ⚠️ 已知文档滞后（2026-08 实测）
- **fund_daily（doc_id=127）文档写「至少 5000 积分」，实际 2000 档即可调**；index_daily（doc_id=95）文档写 2000，与实测一致。
- 铁律：**实测为准，文档仅供参考**。用户声称的权限与文档冲突时，先实测再下结论，别拿文档反驳用户（用户风格：讨厌猜测，要求实际测量）。

## 差分权限探测法（实测推断账号档位）
文档与声称矛盾时，不猜，直接实测。对同一 token 同时调用**已知档位**的多组接口，看 PASS/FAIL 分布推断实际档位：
- 2000 档对照：`fund_daily`、`index_daily`、`moneyflow`、`hsgt_top10`
- 5000+ 档对照：`sw_daily`、`limit_list_d`、`cyq_chips`（通常被拒）
- 判定：能调全部 2000 档、被拒全部 5000 档 → 账号就是 2000 档，且能调通的接口实际门槛=2000。

可直接复用脚本：`scripts/perm_probe.py`（自动取最近交易日，逐接口打印 PASS/FAIL）。

## 运行环境（本机实测）
- 用 mamba 环境绝对路径直接跑：`/Applications/TradingRazer2/bin/python script.py`
- 此 shell 的 PATH 里**没有 conda/micromamba**，`conda run` 会报 command not found —— 勿用，直接调 bin/python。
- TUSHARE_TOKEN 已在 shell 环境 + profile .env 配好（tradingrazer.config 里没有）。

## 频控实战提醒
- 全市场 ETF（1000+ 只）逐只拉 fund_daily：200 次/分钟 → 约 5–10 分钟拉完，10 万次/天配额够用；但循环里**必须节流**（sleep），否则触发频控报错。
