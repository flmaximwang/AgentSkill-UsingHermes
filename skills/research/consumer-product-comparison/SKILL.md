# Consumer Product Comparison（品类 / 品牌 / 具体型号）

## When to Use

Applies to 家电 / 3C / 音频 / 桌面设备 / 家居, and generalises to any spec-driven purchase decision. Users escalate in three shapes — recognise which one you are in and do NOT jump ahead to a model shortlist:

1. **品类 vs 品类**（「玻璃盖式 vs 抽屉式空气炸锅各自优劣」）— 没有型号。走 Step 0.5 建机制模型，每条优劣挂到机制上；结论回答"什么需求选哪一类"。
2. **品牌/系列级**（「X 牌的玻璃空气炸锅怎么样」）— 有品牌无型号。必须先做 Step 1.5 品牌性质核验，评估该品牌在售型号，最后**落到具体型号参数页**（品牌级结论会掩盖同品牌内部的巨大差异）。
3. **2+ 具体型号**（「比较一下 A 和 B」）— 直接走 Step 1→5。

同一会话里这三类常连着出现（品类 → 品牌 A → 品牌 B），每轮复用上一轮已建立的机制模型，不要重讲背景。

Not for: monitoring one product's price over time (that's a price-watch job), or "what should I buy under ¥X" open-ended browsing — narrow the candidates first.

## Step 0 — 先定品类，再比参数

Before pulling any spec, classify each model's **品类定位** (便携电池款 vs 桌面插电款; 一体式 vs 转盘+功放; 小腔体 vs 书架箱). If the two sit in different classes, say so up front and re-frame the axes — a head-to-head "音质" verdict across classes misleads. The class difference belongs in the 一句话结论, not in a footnote.

## Step 0.2 — 术语映射：用户口语 → 社区标准品类名

用户给的品类名常常不是社区标准词（例：键盘圈的「斜配键 / 斜配列」不存在，标准词是 **Alice 配列 / 直列·正交 / 分体式**）。见到不认识的品类词，先**逐字搜索该词**并读社区科普/维基页，判断它是标准词、旧称，还是纯口语；再决定按哪一类比。

映射不唯一时**用 clarify 把候选标准品类名做成选项让用户点**（推荐项放第一），不要凭猜测直接出清单 —— 品类猜错，后面的参数表、价格表、结论全部作废，重做比问一次贵得多。

映射成立后，把「你的说法 → 标准名」这一句写在答复开头：用户下次能自己搜到东西，也知道你按哪一类在比。

键盘/外设类的标准判断轴与比值区间见 `references/keyboard-layout-and-ergonomics.md`。

## Step 0.5 — 机制先行：先定"决定结果的物理量"，再逐条挂优劣

品类对比不能靠罗列卖点。先回答：**这个品类里，决定用户满意度的那一个物理/工程量是什么？** 然后让每一条优劣都成为该机制的推论。用户要"为什么"，不要"看起来有道理"的空话。

1. 写出决定结果的量。空气炸锅 = 食物**表面风速** + 湿气排出速率 + 腔壁对红外辐射的反射率；取暖器 = 出风温度 × 风量；除湿机 = 单位时间除水量。
2. 判断两类在这个量上谁高谁低，给出**方向性**结论。
3. 逐条优劣挂机制："A 类好洗" 是结果，"玻璃光滑无孔隙、无可刮涂层" 才是机制。
4. **机制推出来的结论必须标注为外推**（"按 h ∝ 风速^0.5~0.8 推得"），不许伪装成实测。
5. 先复述自己的假设边界："我理解的两类是指 X 和 Y，不对请纠正" —— 品类描述来自用户口语，猜错整篇作废。

## Step 0.6 — 推导单位强度指标（最有效的降维手段）

把营销参数变成一个可比较的比值，再给出该品类**主流区间**作标尺：**额定功率 ÷ 标示容量**（空气炸锅 W/L）、CADR ÷ 面积（净化器）、除水量 ÷ 功率（除湿机）、亮度 ÷ 功耗（投影）、**元 ÷ 键**、**mAh ÷ 元**（键盘/外设）。

实例：空气炸锅 4–5L 主流 280–425 W/L；某品牌玻璃线全系 108–286 W/L（越低越慢越不脆），而它的非玻璃款 400 W/L 正常 —— **同一个牌子内部，最贵、最被吹的那条线指标最差**。这类反转正是推导指标的价值：它能推翻品牌叙事的排序。用户问"哪个更值得买"时，先给这张比值表，结论往往已经在表里。

比值用 execute_code 算，不要心算，并标注是"本人计算"而非官方指标。

## Step 1 — 品牌官网优先（唯一权威层）

Fetch the manufacturer's own domain first: it carries the authoritative spec table (尺寸/输出功率/蓝牙版本/接口/续航) and the official list price, often in USD too. Brand sites are JS-light and read cleanly with `web_extract`.
Then check whether the model line has revisions — 基础版 / MK2 / 升级款 / Pro / 不同颜色 SKU. Specs, battery and price differ per revision: always state which SKU the numbers belong to, or the conclusion will not match the unit the user actually buys.

## Step 1.5 — 品牌性质核验（品牌级问题必做，型号级也建议做）

先分清这个牌子是**自有品牌**还是**商标授权/贴牌**——两者对"参数可信度、售后责任、品牌溢价合理性"的含义完全不同。完整 playbook（授权识别红牌、价格量级反推、参数分裂表、卖家必问清单）见 `references/brand-licensing-and-spec-verification.md`。三条最小动作：

1. 搜 `"<品牌>" 商标 授权 / used under license` —— 授权方页面页脚常直接写着 `X® is a registered trademark of Y used under license by Z`，这就是"品牌 ≠ 制造商"的一手证据。
2. 查品牌所有者**今天**还做不做这个品类（消费业务被剥离/出售后商标仍在，产品早换人做）。读品牌方的**公司官网**，不是商品页。
3. 看同一品牌下参数是否分裂：多套**型号前缀**、跨多个**产地**、接触食材材质不统一（既有玻璃又有不粘涂层）、标题与参数页矛盾 → 多条授权线/多个代工厂拼盘，"认参数不认牌子"。

## Step 2 — 实机长测（拿官方表格不给的东西）

Sources that earn trust: 什么值得买社区长测, B站实测/续航测试, chiphell 开箱长文, 知乎非 AI 长文。
They yield 喇叭单元尺寸与阻抗、解码/主控芯片型号、电池容量与实际续航、调音合作方、供电模式（是否边充边放）—— the details that decide real-world usability. One long hands-on review beats ten listicles.

## Step 3 — 电商元数据（尺寸/重量/在售 SKU）

京东移动端商品页的 `_itemInfo` JSON 给出 SKU、店铺与箱体尺寸/毛重 —— 那是**物流口径**，不是整机尺寸/净重，写进表格必须标口径。具体 URL、UA 与解析方法见 `web-content-extraction` 技能里的 `china-ecommerce-spec-price-extraction.md`。

## Step 4 — 价格：带日期、分渠道

- 每个价格都带 **来源 + 日期**；分开写 挂牌价 / 到手价（国补、券、活动价常差 20–40%）。
- 跨渠道价差是常态（自营 vs 第三方 vs 海外官网 vs 台湾 momo NT$）。海外与台湾价**不能当大陆价**，只作横向参考 —— 品牌海外官网的 USD 官价与国行价常差**一倍以上**（国行首发价通常更低），两个都报，**绝不用汇率换算出来的数字当国行价**。
- CN 到手价的可采信层是**带日期的中文快讯**：IT之家、in外设、ZOL、什么值得买（首发价 / 到手价 / 券的有效期写得很具体）；只给标题不给价的电商 list 页与聚合站别在那里耗调用。
- 实时价抓不到时明写"未能核实实时价"，只给带日期的数据点。**绝不用挂牌价冒充到手价。**

## Step 5 — 证据分级（必须写进答复）

1. 一手官方规格表 / 官方定价
2. 实机长测（可采信，非官方）
3. 百科/词条类（无来源 → 标"未获官方证实"）
4. AI 生成/聚合内容（知乎标注「疑似 AI 生成」、搜狐/网易「本文包含人工智能生成内容」）→ 只作定性参考
5. 抓不到实时价的项 → 明说

**冲突处理**：两个来源对同一参数给出不同数值时**并列报告冲突**，不取平均、不择一当结论（AI 横评的 频响曲线 与 功率 数字经常自相矛盾）。

## 输出形态（用户期望的形状）

中文行文，保留原始英文/品牌/型号名（Syitren R200、PANDA CD-67、SC6137D）；表格表头与单位用英文：

1. **一句话结论** — 先点出品类定位差异 + 各自卖点
2. **硬参数对照表** — 每行标注来源/口径（官方 / 实测 / 百科口径未证实 / 物流箱口径）
3. **2–4 个决定性差异**，Step 1→Step 2→Step 3 形式，每个差异带具体数字（W、mAh、mm、Hz、元），禁抽象空话
4. **价格一句话** + 版本差异（基础版 / MK2）
5. **证据分级与未证实项** — 收尾固定给一个「证据等级说明」块，按这五类分开写，不要混在正文里：
   - 一手核实（官方参数页 / 授权声明页脚 / 有出处的页面，给链接）
   - 本人计算（推导比值，注明自算）
   - 机制外推（传热/物理推理，注明不是实测）
   - 未查到（本次确实没拿到的：第三方实测、真实口碑、某字段）
   - 明确排除的来源（低质/AI 生成/营销榜单，点名为什么不可用）
6. **下一步选项** — 存 Obsidian 笔记 / 深挖某个轴 / 挂价格监控 / 给一个"下单前必问卖家"清单（参数混乱时这是最有价值的交付物）

听感与参数分开陈述，听感必须标来源；不写"高端大气"式形容。

## Pitfalls

- 物流箱尺寸/毛重 ≠ 整机尺寸/净重 — 电商元数据只给前者，入表必须标口径。
- 同型号不同版本（基础版 / MK2）参数、电池、价格都不同 — 先确认在售 SKU，否则结论对不上用户要买的那台。
- 百科与 AI 横评的参数会互相矛盾 — 并列冲突报告，别择一、别平均。
- 别在价格接口上耗调用次数：京东价格走 JS/登录态，直接用带日期的行情稿或搜索摘要，并标注核验状态。
- 搜索摘要常含页面渲染后的价格文本，即使该页面 curl 被反爬 — 可引用，但要标"未实时核验"。
- 官方页常只给"输出功率"不给频响 — 频响数字若来自第三方，必须标注其证据等级。
- 品类差异（电池 vs 插电、便携 vs 桌面）比单一参数更决定满意度 — 结论里先说这个，再谈参数高低。
- **品牌名可能只是租来的商标** — "德国宝/康宁/杜邦" 这类名字不构成产地、技术或质保的承诺。先做 Step 1.5，再谈参数；不核验就按"外资大牌"处理是最常见的错判。
- **同品牌下材质/产地/前缀分裂时，"认品牌"等于赌博** — 下单前必须锁定**具体型号**的参数页（材质、产地、CCC 编号、功率）。品牌内差异可能大于品牌间差异。
- **价格量级反推材质/技术**（这是推理，必须标"外推"）：某一部件的单品价 ≥ 整机价 ⇒ 整机用的不是那档部件。例：某品牌微晶玻璃锅单只 2.5L 即 ¥700–958，而整台 4L 玻璃空气炸锅只卖 ¥540–635 ⇒ 玻璃只能是普通高硼硅，不可能是微晶玻璃。
- **别把某型号的第三方实测结论套到同品牌其他容量/结构上** — 权威测评测的是 9L 上揭式款（薯条不熟、手柄温升超标），不能套到 4.2L 抽屉玻璃款。引用实测前先核对：测的是哪个型号、哪个容量、哪种结构。
- **标题与参数页矛盾时**（标题写"不沾内胆"、参数页写"内锅材质：玻璃"）→ 以参数页为准、并列报告冲突，并把该矛盾本身当作"这条产品线资料混乱"的证据交给用户。
- **验证不了就不给背书** — 同品类有权威实测、而目标型号没有时，明说"该型号没有任何独立测评"，不要拿品类通用评测替它背书。
- **电商标题是关键词堆砌，不是参数** — 卖家按搜索热度堆词（ABS 塑料壳写成"铝坨坨"、无轴无键帽套件写成"机械键盘"、有线款写成"三模"）。材质/结构/连接一律回品牌官网参数页核，标题只当发现线索；矛盾时以官网为准并并列报告。
- **客制化品类的"套件价" ≠ 到手整机价** — 套件（无轴无键帽）加轴＋键帽通常再 +30–50%。入表必须标"成品 / 套件"口径，否则性价比排序会整体反向。
