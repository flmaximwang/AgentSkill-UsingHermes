# 京东（京东金融「交易流水」导出，CSV）

- 来源键 / 资金科目：`jd`；账户档案 `accounts.jd_baitiao` / `jd_piggy` / `jd_balance` / `jd_loan`
- 导出账号：`7226`（档案 `accounts["7226"]`，内容证据 = 说明块「京东账号名：jd_5e82ee9ecb501」）
- 档案：`Config/bank_profiles.yaml` → `profiles.京东金融`（`out_dir: 京东金融`）
- 样例：`~/Downloads/京东交易流水(申请时间2026年09月20日00时29分11秒)_163.csv`（20260101–20260831，115 条）

## 文件形态

UTF-8(BOM)。前 21 行是说明块，第 22 行表头，第 23 行起明细：

```
导出信息： / 京东账号名 / 申请时间 / 日期区间：2026-01-01 至2026-08-31 / 导出交易类型 / 导出交易场景
共：115笔记录 / 收入：26笔，0.46元 / 支出：58笔(含1笔部分退款)，3063.92元 / 不计收支：31笔，12485.75元
特别提示（8 条，含「京东快捷支付等非余额支付方式可能既产生京东交易也同步产生银行交易，请勿重复记账」）

交易时间,商户名称,交易说明,金额,收/付款方式,交易状态,收/支,交易分类,交易订单号,商家订单号,备注
```

档案映射：`summary=交易说明`、`category=交易分类`、`method=收/付款方式`，`join_summary: [summary, category]`
→ 中间表摘要形如「白条主动还款｜白条」「鸭腿饭（本店招牌） 默认 等多件｜食品酒饮 其他网购」。

## 解析要点（踩过的坑）

1. **金额带退款括注**：`150.98(已全额退款)`、`74.88(已退款1.92)`。不清洗会被 `money.D` 判成 0.00（静默丢笔）
   → 档案里 `amount_strip` 先剥括注再解析（`parsers.jd.amount_of`，缺 `amount_strip` 直接报错）。
2. **金额语义**：部分退款行的金额是**剔除退款后**的支付金额（74.88 表示原 74.88 − 退 1.92），不要自己再减。
3. **交易订单号不唯一**：① 一笔订单可能拆成「余额 + 白条」两行（两行同号）；② 原消费与它的全额退款行同号。
   所以 `ref_join: [date, ref, method]`（**写档案列键，不是表头中文名** —— 写中文名会取不到值而静默退回兜底单号，
   兜底单号只含日期+金额，同额同日两笔会被账本的「重复流水」护栏丢掉一笔）。
4. **字段尾部带 Tab**，`parsers._clean` 已 strip。
5. **「收/付款方式」是资金出处**（决定 `$settlement` 与去重），取值见过：
   `京东白条` / `京东小金库` / `余额` / `先享后付` / `白条分分卡-微信(南京银行)` / `白条分分卡-支付宝(南京银行)` /
   `白条分分卡-白条` / `中信银行信用卡(0270)` / `中国银行信用卡(9393)` / `中国银行储蓄卡(3358)` /
   `中国银行转账(3358)` / `建设银行储蓄卡(2464)`。
6. **南京银行 = 京东白条分分卡的卡面银行**：京东写「白条分分卡-微信(南京银行)」，微信/支付宝账单同一笔写
   「南京银行储蓄卡(0134)」。它**不是**一张储蓄卡，记成银行存款等于把信用消费当银行支出 → 映射到白条负债。
7. 说明块统计与明细逐笔累加**口径不同**（见「已核验锚点」），不是解析错。

## 与既有账户去重（`books.pair_jd_duplicates`）

京东回单是**订单/支付视角**，同一笔钱常与微信/支付宝/银行两面都出现（京东自己也提示别重复记账）。规则：

| 京东侧「收/付款方式」 | 比对池 | 处置 |
|---|---|---|
| 白条分分卡-微信(南京银行) | 微信 | 京东侧跳过，保留账单侧 |
| 白条分分卡-支付宝(南京银行) | 支付宝 | 同上 |
| 白条分分卡-白条（退款行） | 微信 + 支付宝 | 同上 |
| 中国银行储蓄卡(3358) / 中国银行转账(3358) / 建设银行储蓄卡(2464) | 银行 | 京东侧跳过，**并把京东的商品说明回填进银行侧摘要**（银行摘要只有「网上快捷支付｜网银在线-平台商户」这种壳子） |
| 京东白条 / 京东小金库 / 余额 / 先享后付 / 中信·中行信用卡 | 不去重 | 京东独有信息，保留入账 |

- **必须最先跑**：放在 `pair_card_funded` 之后时，被卡结算的微信行已从池子里消失，京东侧配不上而落进待分类
  （实测：微信 2.00 云裳物联那几笔）。
- **不匹配「中国银行」四个字**：中行信用卡(9393) 不是导入账户（导入的是借记卡 3358），按名字配对会把信用卡消费当银行扣款。
- **金额对不上但确属同笔**：京东「白条主动还款 684.90」对银行「跨行转账 684.40」（2026-08-09，差 0.50）。这种
  「资金动作（还款/转入/取现/充值）+ 银行流水带『京东』+ 差额 ≤1 元」按同笔跳过，差额写进跳过原因，不要静默吞掉；
  金额差必须报给人工确认（它会影响银行那笔的科目定性）。

## 科目转换（京东独有部分）

| 交易说明 | 方向 | 分录 |
|---|---|---|
| 京东小金库收益 | 收入 | 借 短期投资—京东小金库 / 贷 投资收益（不能按转账：买卖双方同一账户 → 无效凭证）|
| 白条主动/自动还款 | 不计收支 | 借 其他应付款—京东白条 / 贷 出资渠道（京东小金库 或 银行转账）|
| 京东小金库-转入（出资=银行卡）| 不计收支 | 京东侧跳过；**银行侧**记 借 短期投资—京东小金库 / 贷 银行存款 |
| 白条取现 | 不计收支 | 京东侧跳过；银行侧「银联入账｜白条贷款」记 借 银行存款 / 贷 短期借款—京东白条取现 |
| 京东商城消费（白条/信用卡/余额）| 支出 | 借 费用（按商品与交易分类定性）/ 贷 白条 或 信用卡 或 京东余额 |
| 笔笔返现 | 收入 | 借 其他货币资金—京东余额 / 贷 营业外收入—返现 |
| 退款-<商品> | 不计收支 | 借 出资渠道 / 贷 原费用（冲减）；退款类型换了科目就另写更窄的退款规则放上面 |
| 先享后付 0.00 | 不计收支 | 金额 0 → 计入笔数不入账 |

## 已核验锚点（源文件 20260101–20260831，115 条）

| 项目 | 文件自带统计 | 明细逐笔累加 | 差异 | 原因 |
|---|---|---|---|---|
| 笔数 | 115 | 115 | 0 | — |
| 收入 | 26 笔 0.46 | 26 笔 0.46 | 0.00 | — |
| 支出 | 58 笔 3063.92 | 58 笔 3065.84 | −1.92 | 部分退款行（京东已剔除退款金额 1.92） |
| 不计收支 | 31 笔 12485.75 | 31 笔 15526.63 | −3040.88 | 6 笔「已全额退款」行京东不计入统计 |

拆成 8 份按月文件（202601–202608）后的复核结论：每个文件「总行数 = 说明块 22 行 + 表头 1 行 + 本月笔数」，
逐文件解析的笔数/收支合计 = 源文件逐笔累加分月结果，「日期/金额/收支/交易单号/说明/商户」多重集拼起来全等。

京东 115 行的最终去向（202601–202608 合计）：入账 57 笔（小金库收益 24、白条还款 6、12306 4+2 退款、
京东外卖 5、平台购物若干、物流 1、笔笔返现 2）、配对跳过 54 笔、零金额 3 笔、待分类 1 笔（27.86，
财付通(银联云闪付) 用白条分分卡付款，微信账单里没有对应笔）。
