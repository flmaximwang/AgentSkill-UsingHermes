# 子代理任务书与收据

`dream` 的分工落到可抄的文字。四条通则，然后四份任务书。

## 通则（每条任务书都要带上）

1. **前台跑完即结束，不起后台进程。** 子代理起的后台进程退出时，完成通知带的是**子代理自己的 session id**，
   网关会把它当成这条 chat 的路由拥有者，把路由 pin 到子代理身上——人面会话被顶掉、真正的委派结果被丢弃。
   长命令用高 timeout 的前台调用。
2. **只认落盘产物。** 批次完成通知里的摘要会把长 picks 截成 `…(+100 chars)`，live transcript 也可能被截；
   判官/分类子代理一律 `write_file` 落盘，回答里再原样重复一遍。
3. **子代理不能提问，主 agent 也不提问。** 本 skill 无人值守：任务书里不许出现「等用户确认 / 等批准」；
   子代理只返回事实与建议，决议按 S4 的规则做；需要人拍板的行留本地并列进汇报。
4. **只给它该看的东西。** 任务书里写死「只读哪几个文件」，别让它去翻技能目录、翻内存、翻别的包——那是另一
   条子代理的活，串味的判断比没有判断更贵。

## A. 分类子代理（S2，JEV 不可用时；每 8–12 条一个）

```
你是技能归位判官。为每条候选技能判一个落点包 —— **每条都必须有落点，没有「留本地」这个答案**。

材料（只读这几个，不要翻别的目录、不要读内存、不要读别的包）：
  <SCRATCH>/judge-input.json        候选：id / skill / category / description / **skill_md 绝对路径** / refs
  <SCRATCH>/answer-space.json       落点空间：dirs / tool_dirs / topic_dirs / routable
  <SCRATCH>/pack-index.txt          可路由包的各条 category/name: desc（判「并入哪条已有技能」时看它）

**纪律（违反其中任何一条，这条 verdict 作废）**
1. **必须读全文**：对你负责的每一条，用 read_file 打开它 `skill_md` 指的那个 SKILL.md **整篇**
   （正文点了名的 references/ 文件也要读）。**禁止只看 name / description / category 就下结论**
   —— 那是机械判法，用户已明确驳回。
2. **每条都要有一段正文证据**：`evidence` 字段填正文原句，或 `file:line`。填不出来的算没判。
3. **每条独立判**：同一类目下的技能可以落不同包；**禁止按类目批量套模板**（「obsidian/* 全进
   ObsidianManagement」「profile 私有 → AgentSkill-Private-<Profile>」这类映射已被用户驳回）。

**三段问法**（一条一条按顺序答，别跳）
1. **轴**：这条技能的**主语**是「某个软件/工具」还是「一类任务/学科/项目」？
2. **落点**：该轴里哪个目录名？从 answer-space.json 的 tool_dirs / topic_dirs 里挑（**照抄，不许自己造名字**）。
   现有目录都不覆盖它才答 new，并给 axis + topic + **boundary（这个包不吃什么，必填）**；
   主题名要少、同类合并（一主题一包）；这条只关你本地这台机器的私有流程，仍要落主题包，别自己发明
   `AgentSkill-Private-<Profile>` 这种垃圾抽屉。
3. **落点技能**：落点是已有目录时，并入它已有的哪条技能（从 pack-index.txt 抄，或答 __new__）。
   正文没给你接收侧正文，所以**重叠不要在这一轮下结论**，只在 why 里点出可疑的那条名字。

这条例外要标出来：技能**自报上游仓库**（目录里带 `_meta.json` / `skill-card.md`，或正文头部写着
`GitHub: <url>`）时，照常给落点，但 `why` 以 `upstream:<owner>/<repo>` 开头。

产出：把结果**写进** <SCRATCH>/verdicts-task-<N>.jsonl（每行一条 JSON，不要代码块包裹）：
{"id":"P12","dest":{"kind":"existing","repo":"AgentSkill-UsingGit","dest_skill":"__new__","action":"move"},
 "why":"…","evidence":"正文：「…」","confidence":0.82,"source":"agent"}
{"id":"P13","dest":{"kind":"new","axis":"tool","topic":"Jev","personal":false,"boundary":"不吃编辑器接入"},
 "why":"…","evidence":"…","confidence":0.8,"source":"agent"}
  action: move（整条迁进包）/ merge（内容并进 dest_skill）/ strengthen（两边头部各加一句界限声明）
  source 一律写 agent（你不是 JEV）。写完在回答里原样重复这几行。

**先把 JSONL 写完再回答**：回答里只给「条数 + 每条一行」，正文以落盘文件为准。
```

## B. 交叉审计子代理（S3，**每个目标包一个**）

同一包的候选共享接收侧技能，合起来审比拆开审准：一个判官能同时比较「这条该并入哪条已有技能」与
「这几条之间是不是本来就该合成一条」。一包里候选多时分波也行，但同一包的判官要看到该包全部候选。

```
你要证明一条 profile 本地技能与一条包内已有技能重叠在哪，只出证据与建议，不动任何文件。

材料（全部读完，别跳）：
  源：<PROFILE>/skills/<类目>/<本地技能>/          SKILL.md + references/ + scripts/
  接收：<PACK>/skills/<接收技能>/                  同上

做法：逐个 claim 地在两边 grep（表头、实测数字、命令旗标、源路径、报错原文），
按 `maintain-hermes-skills-overlap-and-merge.md` §2 的口径：
- 命中接收侧算 already there，**必须**给出接收侧的 file:line；给不出行号的算 net-new。
- 同一个词两边含义不同时以读到的正文为准，不许按词面判重叠。
- 报告两张清单，不要写「两者有一定重叠」这种结论。

产出 <SCRATCH>/overlap-<P id>.md：
  ## already there   （每条：源里的哪一句 → 接收侧 file:line）
  ## net-new         （源里有、包里哪里都没有的原子项清单）
  ## 建议            merge | new | strengthen + 一句理由 + 若 merge，折进哪个 references 文件
回答里给三个小节的标题与计数，正文以落盘文件为准。
```

## C. writer 子代理（S5，每个目标包一个）

```
你只负责 <PACK>（clone: <路径>，标识符 <owner/repo>，类目 <category>）。别的包、别的会话的文件一个字都不要动。

按规则决议后的行（来自 plan.md，逐字照做，不要自行增减）：
  <P 12> localskill → 新技能 skills/localskill；内容来源 <PROFILE>/skills/<类目>/localskill/（整目录读完）
  <P 30> otherskill → 并入已有技能 skills/<接收名>（overlap-<id>.md 里 net-new 的那一节才是要折进的内容）

顺序（硬来，别跳）：
1. git fetch --quiet && git status --short && git log --oneline -3 origin/main
2. 若 <PROFILE> 里同名副本比仓库新（别的会话在途的工作）：先逐字节回移植，**单独一个提交**，再改你的。
3. 写内容，沿用本包形状：frontmatter 只有 name + description（<技能名> 与目录名一致）、
   references 命名 <skill>-<topic>.md、正文末尾带两行 Generated by Scripts 注释标记、兄弟脚本用
   `../../<兄弟技能>/scripts/<x>.py` 定位并给 —— 覆盖参数。
4. 预测扫描 verdict（tools.skills_guard.scan_skill）：非 safe 就按命中形态改写文字（保留命令与路径、
   只去「长得像那个动作」的写法），rewrite 后再扫；dangerous 不许推。
5. python3 scripts/auto-generate-skill-structure.py <技能名>
   python3 scripts/verify-skill-package.py skills/<技能名>          # 要 tree vs disk: ok 与 pointers: ok
6. git add skills/<技能名>（pathspec，不许 -A）→ git diff --cached --stat 自查 →
   git commit -m "docs(skills): <中文说明>" → git push origin <你的 sha>:main
7. 从远端回读：git log --oneline -1 origin/main 必须是你的 sha。

回执（缺一件就不算交付）：commit sha · 推出去的 sha · 扫描 verdict + findings 条数 ·
git diff --cached --stat · 你**没有**碰过的路径清单（如果你 checkout 了别人的漂移文件，在这里说明）。
前台命令跑完就结束，不要起后台进程。
```

## D. 验证子代理（S6，与所有 writer 不同的一条）

```
只读复核 <SCRATCH>/plan.md 的每一行，逐行给 PASS / FAIL，**不要修复任何东西**。

对每行核六件：
 1. git -C <PACK> ls-tree -r --name-only origin/main | grep '^skills/<技能名>/'   非空
 2. git -C <PACK> log --oneline -1 origin/main          == plan 里记的 sha
 3. hermes --profile <profile> skills check <技能名>     == up_to_date   （一次只吃一个名字）
 4. diff -rq <PACK>/skills/<技能名> <PROFILE>/skills/<类目>/<技能名>   无输出
 5. .hub/lock.json 里 installed.<裸名>.metadata.source_revision == 仓库 HEAD
 6. cd <PROFILE>/skills/<类目>/<技能名> && python3 -B scripts/<脚本>.py <一个只读参数>   退出码 0

产出 <SCRATCH>/verify-report.md：一行一结论（P id / 六项的逐条结果 / PASS 或 FAIL + 原文报错），
外加一节「对不上但可能是我看错的地方」。回答里给 FAIL 行的清单与总数，正文以落盘文件为准。
```

## 分波与并发

- 分类子代理与 writer 子代理并发上限都是 **10**；超过就分波，每波 ≤10，等一波回执齐了再派下一波。
- 交叉审计子代理通常只有几条，和分类子代理不同波（它依赖 S2 的结果）。
- 验证子代理**只在全部 writer 结束后**派一条，别按包派多条（六件事里有三件要等 plan 全部落地）。

## 回执对不上时的处置

| 症状 | 处置 |
|---|---|
| 子代理说「完成」但 `origin/main` 不是它报的 sha | 不信自述：那是未推送，回 S5 重做那一条包 |
| clone 里出现你的 pathspec 之外的改动 | 是别人的在途工作或生成段漂移：`git checkout -- <它们>`，列进汇报，不要提交 |
| 装好的副本 `update` 报「kept your local edits」 | 副本里被跑出 `__pycache__`：删掉再 update；预防是跑副本一律 `python3 -B` |
| 子代理超时 / 上下文爆 | 把任务拆小（一个包拆成两个包、一批 15 条拆成两批），别加大超时硬扛 |
| 验证行的 `check` 报 `update available` | 那是远端已被别人推新：先看是不是本次内容，再决定 update 还是报告 |
