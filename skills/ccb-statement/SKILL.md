# 建设银行个人活期账户流水（PDF）

- 账户 / 资金科目：`建设银行储蓄卡-2464` → `accounts.ccb_card`（1002 银行存款）
- 档案：`config/bank_profiles.yaml` → `profiles.建设银行`
- 样例文件：`~/Downloads/流水/建设银行/中国建设银行_2464_20260801_20260831.pdf`（1 页）
- 导出账号：`2464`（档案 `accounts["2464"]`，内容证据 = 抬头「卡号/账号：6217000010182242464」）

## 文件形态

标题「中国建设银行个人活期账户全部交易明细」，表头上方有两行信息：

```
卡号/账号:... 客户名称:... 币别:人民币元 钞汇:钞 起止日期:20260801-20260831
当前时间段收支金额合计：人民币元； 总支出：93.28      总收入：0.00     ← 对账锚点
```

表格列：

```
序号 | 摘要 | 交易日期 | 交易金额 | 账户余额 | 交易地点/附言 | 对方账号与户名
```

## 解析要点（与中行的差异，必须按银行档案区分）

1. **锚列不是第一列**：第一列是「序号」，日期在第三列。判定「新记录开始」要看
   **日期类列**（`pdf_table._ANCHOR_HINTS`），否则一条记录都抽不出来（会全部当成续行）。
2. 金额单列带符号（负=支出）；交易日期是 `20260803` 无分隔符格式。
3. 页面底部有「生成时间」「温馨提示」「- 第1页/共1页 -」，需跳过。
4. 对方账号与户名被银行脱敏（`Z

******0010/*玉丽` 这类），**不能据此判断科目**，只能靠摘要。

## 科目转换

| 摘要 | 分录 |
|---|---|
| 代理付款（对方 = `11001018000058022443/中国科学院大学`） | 奖学金收入：借 银行存款—建行卡 / 贷 `5301 营业外收入—奖学金收入` |
| 消费（无明确用途、对方已脱敏） | 待分类（脱敏信息不足以定科目） |
| 充值（对方为个人、金额与平台充值一致） | 先与对应平台流水配对；配对成功则并入平台侧，否则待分类 |

该账户仅 4 条记录（2026-08），样本不足以固化规则；新增月份流水后应扩充本 skill 的对照表。

- 支出合计 **93.28** / 收入合计 **0.00** = PDF 上方「总支出/总收入」声明值，逐分一致

该卡的主要交易模式：每月「代理付款 +1,500」到账后当日/次日「跨行转出」到本人中行借记卡（6235710800000363358）
→ 属**自有账户间划转**，不是收入/费用；2026-03 起还出现「利息存入 0.04/0.01」。

对方卡号 `6235710800000363358` 已登记在 `Config/account_map.yaml` 的 `own_accounts`（→ `boc_card`），
规则 `own-account-move` 记成 借 银行存款—中行借记卡-3358 / 贷 银行存款—建行储蓄卡-2464。
**同一笔在中行侧还有一条「跨行转账 in←2464」**，由 `books.pair_own_account_transfers` 配对：
只留转出侧（本卡这一条），中行侧写进「配对与问题」—— 两侧各记一张会把两个账户的发生额各放大一倍。
对方账号若未登记，`book`/`month` 会**报错停下**（不写账本），修法是补 `own_accounts` 而不是忽略报错。

## 按月拆分（PDF 专用）

银行 PDF 不能整页复制（这份整份只有 1 页却跨 6 个月）。`python -m Scripts split <pdf>` 会**按抽出的明细重排**
生成派生件：保留原列名与原取值、页首标注「派生件（非银行原始回单）+ 源文件名 + 卡号/客户 + 期间 + 本页笔数/支出/收入」，
写盘前回读自检。抬头里的「页数 1/31」「借方发生数」「行数」等只对原件成立的数字**不得**搬进派生件。

## 「对方账号与户名」折行：CELL 画在数据行的**上下两侧**（已修，别再按旧行为解释）

建行把这一格画成两条物理行：`11001018000058022443/中国科学院` 排在**数据行上方**，`大学` 排在**下方**。
修改前 `pdf_table.extract_rows` 把无日期的续行一律并进**上一条**记录 → 上方那半截串进上一条
（`Z

******0010/***新伟11001018000058022443/中国科学院` 这种拼接垃圾），本行只剩最后一截：
**「中国科学院大学」被读成「大学」**，6 笔 1,500 元的奖学金因此认不出对方是谁。

修法：续行按「与上一条锚行 / 下一条锚行的**垂直距离**就近归属」（近上=前置拼接、近下=后置拼接），
上下两种折行排法都能正确还原。金额/日期/余额本来就不受影响。

- 改动位置：`pdf_table.extract_rows`；改后对全部 PDF 逐字段复核：**中行 452 行零差异**，
  只有建行这 6 笔 1,500 的户名由 `大学` 恢复为 `11001018000058022443/中国科学院大学`。
- **解析器改过之后，按月派生件必须重拆**（`split <源文件> --force`）：派生件里存的是旧解析结果，
  不重拆就永远还是「大学」。重拆前先 dry-run 看笔数/收支合计与源文件声明值是否逐分一致。
- 派生件一行一笔、不折行，因此重拆后回读稳定（自检会逐笔比对源明细）。
