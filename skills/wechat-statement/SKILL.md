# 微信支付账单（XLSX）

- 账户 / 资金科目：`微信零钱-零钱` → `accounts.wechat`（1012 其他货币资金）
  - 实际用信用卡结算的流水 → `accounts.boc_credit`（2241 其他应付款—信用卡），不是零钱
- 档案：`config/bank_profiles.yaml` → `profiles.微信`
- 样例文件：`~/Downloads/流水/微信/微信支付账单流水文件(20260801-20260831)_20260919213044.xlsx`
- 导出账号：`7226`（档案 `accounts["7226"]`，内容证据 = 说明块「微信昵称：Geobacter sulfurreducens」
  —— 微信账单里没有账号数字，只能靠昵称认）

## 文件形态

- 单工作表，**前 16 行是说明**（微信昵称、起止时间、导出类型、导出时间、共N笔记录、
  收入/支出/中性交易统计、注 1-4），第 17 行是分隔线
  `----------------------微信支付账单明细列表--------------------`，**第 18 行才是表头**。
- 11 列：

```
交易时间 | 交易类型 | 交易对方 | 商品 | 收/支 | 金额(元) | 支付方式 | 当前状态 | 交易单号 | 商户单号 | 备注
```

## 解析要点（踩过的坑）

1. **交易时间是 Excel 日期序列值**（如 `46265.72846064815`），必须按日期单元格读
   （openpyxl `data_only=True` 会给出 datetime），当成字符串会得到一串数字。
2. `金额(元)` 在导出里可能是数字也可能是 `¥1,234.56` 字符串；统一按文本清洗（剥 ¥、千分位）。
3. `收/支` 取值：`收入` / `支出` / `中性交易`（充值、提现、零钱通存取、信用卡还款等）。
4. 文件尾部有「总交易单数」等汇总行，需跳过。
5. `支付方式` 指明真实出资渠道：`零钱` / `中国银行信用卡(9393)` 等。
   写「信用卡」的流水要记 **2241 其他应付款**（负债），不能记成银行存款减少。

## 科目转换（该账户常见交易）

| 交易类型 / 对方 | 分录 |
|---|---|
| 分分捐、腾讯公益慈善基金会、春蕾计划 | 借 营业外支出—公益捐赠；贷 结算账户 |
| 堂食/餐饮/小吃/奶茶 | 借 管理费用—生活支出-餐饮；贷 结算账户 |
| 微信转账（个人），收支不明的 | 待分类（借入还是收回需人工判断） |
| 零钱提现至银行卡 | 借 银行存款（到账额）+ 借 财务费用—手续费；贷 其他货币资金—微信零钱 |
| 商户消费且支付方式为信用卡 | 借 费用；贷 其他应付款—中国银行信用卡 |
| 云裳物联等无法识别用途的商户 | 待分类 |

## 跨期导出按月拆分（`split`）

```bash
cd /Users/maxim/Documents/Obsidian/wangfanlin4_Accountancy
env -u PYTHONPATH /Applications/Accountancy/bin/python -m Scripts split "<文件>" [--dry-run] [--force]
```

- 产物落 `Running Account/微信/微信_7226_YYYYMMDD_YYYYMMDD.xlsx`：复制源工作簿的说明块
  （第 1-17 行，合并区 A1:K1…A17:K17）、表头与本月数据行，**日期单元格与日期格式原样保留**
  （是 datetime，不是文本）；「共N笔/收入/支出/中性交易」按本月逐笔累加重算，说明块里加一行「拆分说明」。
- **数据行必须重编行号**：源文件里 1 月的行在第 181-199 行，直接照原行号复制会得到「18 行说明 +
  一大片空行」的废件（已踩）——`split` 用「源行号→目标行号」映射修正。复核时必须核对
  每个按月文件「总行数 = 18 + 本月笔数」。
- 多期原件必须留在 `Running Account/` 之外（否则全期 + 按月重复入账，`split` 会拒绝）。
