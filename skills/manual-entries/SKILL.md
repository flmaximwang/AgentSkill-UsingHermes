# 人工补录（不是任何机构的导出文件）

- 账户 / 资金科目：`人工补录` → 档案里的 `money_account: alipay_piggy`（只是兜底，规则应显式给 `money`）
- 档案：`Config/bank_profiles.yaml` → `profiles.人工补录`
- 目录：`Running Account/人工补录/人工补录_YYYYMMDD_YYYYMMDD.csv`（**一个月一个文件**）
- 来源键：`来源 = "manual"`（档案里 `source: manual`，由 `parsers.manual` 解析）

## 什么时候才能用这个来源

只用于「**确实发生过、但你手上的账单里读不到**」的资金进出。典型：支付宝**共享小荷包**
（恋爱小金库）里对方的钱被转到本人银行卡并投进证券账户 —— 本人账单只记自己那一腿
（当月从小荷包转入 1,000、小荷包转出到银行卡 3,000），对方转入池子的 2,000 在**对方账单**里。

**绝不允许**用它补「银行入账」：银行流水逐分勾稽（余额列），补一笔就报差；补录没有余额列，
只做条数勾稽（与平台账户同理）。有原始流水能证明的事 → 写**规则**，不补录。

## 业务类型清单（每条补录自己点名；一个入口装多种业务）

| 业务类型 | 谁生成 | 分录 |
|---|---|---|
| `共同财产转入` | 人工（对方账单读不到的那一腿） | 借 1012 小荷包 / 贷 5301 个人转入（非借款） |
| `折旧计提-<资产ID>` | **`python -m Scripts assets --write` 按 `Config/fixed_assets.yaml` 台账生成** | 借 5602 生活支出-折旧 / 贷 1602 累计折旧（**不动货币资金**） |

**折旧行由脚本覆盖写**：位置、金额、摘要、交易单号全部由台账算出，`--write` 会先删掉本类旧行再写
（幂等，重跑不重复累加）—— 手工改折旧行会被下次运行冲掉，要改就改台账（`Config/fixed_assets.yaml`）
再重跑 `assets --write` + `book`。**非折旧行（共同财产转入等）由脚本原样保留**，不许丢。

## 文件形态

```
# 说明块（# 开头，逐行写：这不是原始回单 / 场景 / 业务类型 / 本业务分录口径 / 确认人+日期 / 警戒）
日期,业务类型,对方,摘要,收支,金额,交易单号,状态,结算方式
2026-03-05,共同财产转入,郑玉丽,"共同财产转入（共享小荷包）：池内 2,000 属对方转入",收入,2000.00,MANUAL-JP-20260305,人工补录已确认,
```

- 共 9 列，**列数必须与表头逐列对齐**（档案开了 `strict_columns`）；上例的 `摘要` 含半角逗号，
  所以整体加了双引号 —— 用 `csv.writer` 写会自动处理，手写时必须自己加。
- `收支` 用中文值（`收入`/`支出`/`不计收支`），金额一律正数 —— 与其它来源同一口径。
- `交易单号` 必预唯一（建议 `MANUAL-<业务>-日期`）：重复会被「重复流水」护栏丢掉一笔。
- `业务类型` 是**人工点名**的字段（见下）。

## 业务类型：补录是入口，不是业务

**不要**写 `{sources: [manual]}` 这种来源级兜底规则 —— 它会把将来的「对方取回」「手工更正」
一并吞掉（与「平台购物规则吞掉还款」是同一个坑）。正确做法：

1. 每条补录在 `业务类型` 列点名业务（如 `共同财产转入`）；
2. `Config/account_map.yaml` 里写一条**按业务类型**匹配的规则：
   `when: {sources: [manual], business_any: ["共同财产转入"], direction: in}`；
3. 没点名 / 点错名 / 没有对应规则的业务类型 → **不命中 → 待分类**（不猜、不按来源笼统入账）。

`business_any` / `business_not_any` 匹配的就是记录里的 `业务类型`（`parsers.normalize` 从档案的
`columns.business` 取值；`REC_COLUMNS` 里也有一列，其它来源为空）。

**业务类型必须一眼可见**（踩过：只在中间表有值，账本里看不见，被 entry_type 的通用标签盖住了）：
补录行的 `业务类型` 就是凭证摘要的**首段**（`books._summary`），也是「规则命中」表的「条目类型」。
所以凭证长这样：`共同财产转入｜郑玉丽｜共享小荷包池内 2,000 属对方转入，本人同期出资 1,000`——
补录行的摘要文本不要再重复写一遍业务类型的词。

## 陷阱（踩过的）

- **重写文件时「读回 0 行」会把别的业务的行整批丢掉（静默）**：用 `csv.DictReader` 只喂「表头之后的
  正文」时，它会把那**第一行数据当成表头**吃掉 → 读回 0 行 → 覆盖写只剩本次生成的行。
  踩过：2026-07/08 的「共同财产转入」行被 `assets --write` 静默删除。两道防线：
  ①`csv.DictReader(..., fieldnames=<列名>)` 显式给列名；
  ②**写临时件 → 回读自检（保留行数 + 本次生成行数都要对上）→ `os.replace` 落盘**，
  对不上就抛错、绝不落盘（与 `split.py` 对 PDF 派生件的纪律同一套）。改完必须重新核对每个文件的
  数据行数与金额合计，并确认原有的非折旧行还在。
- **半角逗号会把列冲歪，而且是静默的**：`摘要` 里写 `本人同期出资 1,000`，那个半角逗号让后面所有
  列左移 —— 不会报错，只会把「收入/2000.00」读成「收支=000、金额=收入」，那笔变成 **0.00 元中性流水**。
  两道防线：①档案开了 `strict_columns: true`（列数≠表头就报错）②字段含半角逗号时用 `csv.writer` 写
  （自动加引号），或改用全角逗号/「，」。
- 说明块里**不要**出现 3 个以上列名（`日期/业务类型/对方/摘要/收支/金额/交易单号/状态/结算方式`），
  否则 `find_header_index` 可能把说明行当表头。
- `摘要` 里避免「提现 / 转出到卡 / 转出到银行卡」等提现关键词（`books._PLATFORM_WITHDRAW`）：
  目前它对 manual 不生效（只扫 alipay/wechat 与银行侧），但写上去等于埋管。
- 补录文件**不要**与真实导出混放、也不要导一份全期文件 + 按月文件（同笔钱会被各解析一遍）。

## 分录口径（当前：共同财产转入 → 按收入）

```
借  1012 其他货币资金—支付宝小荷包        2,000.00
  贷  5301 营业外收入—个人转入（非借款）    2,000.00     ← 共同财产关系，按收入计，不做价税分离
```

改回「代持」口径（借 1012 / 贷 2241 其他应付款—代投证券款）只需把规则的 `entry_type` 换成
`held_in` + `params: {held_account: daichi_securities}` —— **流水文件不用动**，两者差的就是
「净利润 +2,000/笔 且有负债 2,000/笔」。
